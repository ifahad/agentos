The platform

Everything an agent needs to run in production.

One governed operating layer — from improving agents to shipping and scaling them, with the observability and evaluation to trust what they do.

01Engine

Self-improving agents

The reflection loop proposes prompt improvements, auto-evaluates candidate against baseline, and ships only what a human approves.

eval-gated · human-approved
02Observability

See exactly what agents do

OpenTelemetry traces, a bundled Langfuse profile, and a per-key audit log of every served model call — plus tool steps and council verdicts recorded in the runtime, all attributable.

otel · langfuse · audit
03Evaluation

Score and gate performance

Eval suites with an LLM judge measure agents against real cases, and an opt-in CI gate fails a build that scores below your threshold.

llm-judge · ci gate
04Deployment

Ship and scale in production

Docker Compose for a laptop, a Helm chart for a cluster — non-root images everywhere but the optional browser connector, and in Helm a hardened security context on the gateway, runtime, sandbox, console and connectors; the sandbox drops all capabilities on a read-only rootfs in both.

compose · helm · non-root
05Sandbox

Run generated code safely

Agent-written Python executes in an egress-less Rust sandbox: read-only rootfs, every capability dropped, no route to the network.

egress-less · rlimited
06Fleet

Agents for the whole company

Multi-tenant orgs, roles, and per-tenant budgets and rate limits. SSO and SCIM provisioning put every team on the same governed gateway.

rbac · sso · scim
Why AgentOS

Governance isn't a setting. It's the architecture.

The runtime holds no provider credentials. Every model call is issued through the gateway on a virtual key, so it is impossible for an agent — or an autonomous loop — to route around the budgets, limits, and audit that make it accountable.

Attributable01

Every action has a name

Virtual keys and orgs mean each request is traced to the key and tenant that made it and what it cost — never an anonymous provider call.

Bounded02

Nothing runs unbounded

Atomic budget reservation stops a fan-out from overrunning; every autonomous run is bounded by a cycle cap, and the council carries a kill switch.

Safe by default03

Read freely, propose writes

An unattended council member reads on its own but turns every write into a human-approved proposal — fail-closed, so an unknown tool is a write.

Multiverse council

Many models. One verdict. Honest dissent.

Route one objective to a council of model-bound agents, each on a different model — five local models out of the box, frontier models when you enable them. A judge synthesizes their answers into a single verdict — and reports where they disagreed, instead of averaging it away.

  • / Call the whole council behind one OpenAI-compatible model name.
  • / Quorum and failure isolation — one bad vendor never denies the verdict.
  • / Two independent guards stop the council calling itself.

Operators

Governed autonomy — on a schedule, or a webhook.

Standing objectives the runtime pursues on its own: fire on an interval, a cron schedule, or an inbound webhook. Every run is governed and bounded by a cycle cap, and on the default react profile any tool you put on the approval list pauses for a human. The scheduler is opt-in and off by default.

  • / interval · cron · webhook triggers toward stored objectives.
  • / A run that needs approval is recorded, never auto-resumed.
  • / In-repo, checksummed skills the agent pulls on demand — never a registry.

Sovereign by design

Your agents. Your keys. Your infrastructure.

✳ Zero external services

The whole platform runs on your own hardware — gateway, runtime, sandbox, database. Point it at local models and no third party sees a prompt.

✳ Runs air-gapped

Local models mean a full five-model council answers at $0 with no internet at all. Bring frontier keys when you want them.

✳ Credentials never leave

Provider keys live in the gateway behind a pluggable secrets backend — env, encrypted file, or Vault — and the runtime never holds one.

Get started

Stand up a governed agent platform in one command.

Clone the repo, docker compose up, and open the console. Point it at a local Ollama and the whole stack — including the five-model council — runs on your machine at $0.

quickstart 
$ git clone <repo-url> agentos && cd agentos$ cd deploy && cp .env.example .env# set AGENTOS_ANTHROPIC_API_KEY, or point AGENTOS_OLLAMA_BASE_URL at a local Ollama for $0$ cd .. && make up$ make smoke

Then open the console at localhost:3000 and sign in with your admin key.
